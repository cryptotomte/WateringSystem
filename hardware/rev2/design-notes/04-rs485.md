# Block 4 — RS485 / sensor interface (rev2 node)

**Status:** Draft for review · 2026-06-24 (was STUB — open items now resolved
against the THVD1426 datasheet SLLSF87A)
**Scope:** THVD1426 auto-direction transceiver wiring, A/B termination + bus ESD,
the **control side** of the switched 12 V sensor rail (gate driver + the
`SENS_GATE` seam), and the Modbus/sensor connector J4.
**Out of scope:** power path of the sensor rail (block 1 §1.4 — Q21, the high-side
P-FET, is placed there); pump / I²C / MCU blocks.

**Refdes convention:** reused BOM refdes **U3** (THVD1426), **R3** (120 Ω term),
**D4** (SM712 bus TVS), **J4** (4-pin sensor connector). New parts use the
**60-series** — ⚠️ *the old stub said 50-series, but block 3 (USB-UART) took the
50s; corrected to 60s here.* This file is the source of truth for *connectivity*,
not numbering. **R4/R5 (the old 680 Ω bias pair) are removed** — see §4.2.

**Net naming** (1:1, aligned with rev1 `RS485_TX`/`RS485_RX`):

| Net | Meaning |
|---|---|
| `RS485_TX` | MCU UART2 TX → transceiver D (DI) |
| `RS485_RX` | transceiver R (RO) → MCU UART2 RX |
| `SENS_PWR_EN` | 3V3 GPIO — enables the sensor rail **and** the transceiver (SHDN̅) |
| `SENS_GATE` | gate of the block-1 high-side P-FET (Q21); pulled low here to turn the rail ON |
| `RS485_A`, `RS485_B` | the differential bus pair to J4 |

rev1's combined `RS485_DE_RE` direction line is **gone** — THVD1426 is
auto-direction (no DE pin), so no direction GPIO is needed.

### Hierarchical labels (sheet pins) — place these on the sheet

Four signals cross the module boundary → **hierarchical labels**; the shape is from
this block's point of view (matches `00-architecture.md §0.5` rs485-sensor).

| Hierarchical label | Shape | Inside this sheet connects to | Other end |
|---|---|---|---|
| `RS485_TX` | **input** | U3 D (pin 4) | mcu IO16 |
| `RS485_RX` | **output** | U3 R (pin 1) | mcu IO17 |
| `SENS_PWR_EN` | **input** | Q60 gate (+ R60 pulldown) + U3 SHDN̅ (pin 3) | mcu IO25 |
| `SENS_GATE` | **output** | Q60 drain | block 1 — Q21 gate |

**Rails are NOT hierarchical labels** — `+3V3`, `GND`, `VBAT`, `SENS_12V` are placed as
**global power symbols** (§0.3). And `RS485_A`/`RS485_B` are **local** to this sheet
(they terminate at connector J4, a board edge — not a module boundary), so they get
**no** hierarchical label either.

## 4.2 Key decisions (open items resolved against SLLSF87A)

1. **External A/B bias (R4/R5) — REMOVED.** THVD1426 has a **built-in receiver
   fail-safe**: the receiver thresholds are offset negative (V_IT+ = −45 mV max,
   V_IT− = −200 mV min, V_HYS ≥ 30 mV), so an open / idle / shorted bus (≈0 mV
   differential) reads a **defined logic HIGH** with no external bias. This is a
   named datasheet feature (§9.2.1.4). Dropping R4/R5 also removes the ~2.2 mA
   continuous idle draw they caused — closing the old Open Item 2.
2. **`SHDN̅` (pin 3) — tie to `SENS_PWR_EN`** (recommendation; confirm). Active-low
   shutdown drops ICC from ~1.7 mA to **3 µA typ**. Gating it with the same GPIO
   that switches the 12 V rail means the transceiver sleeps in lockstep with the
   sensor (the node already duty-cycles the sensor to save battery), **with no
   extra GPIO**. Polarity matches directly: `SENS_PWR_EN` HIGH → rail ON + SHDN̅
   HIGH (active); LOW → rail OFF + SHDN̅ LOW (shutdown).
   *Alternative if you prefer simplicity over the µA:* tie `SHDN̅` → `+3V3`
   (always active, ~1.7 mA continuous).
3. **`RE̅` (pin 2) — tie to `GND`** (receiver always enabled). Simplest with
   auto-direction; the node hears its own TX (echo on RO) — firmware discards it
   (trivial at 9600 baud). No GPIO. *(When SHDN̅ shuts the part down, RE̅ is moot.)*
4. **Termination — single 120 Ω (R3) on this board.** Short point-to-point run to
   one sensor at 9600 baud. ⚠️ **Confirm the sensor doesn't embed its own
   terminator** (many NPK probes do) — if it does, this becomes a both-ends 60 Ω
   bus; still fine for fail-safe (no bias to undersize now), but R3 may then be DNP.
5. **Bus ESD (D4 = SM712) — keep.** The THVD1426 already has ±12 kV IEC 61000-4-2
   on A/B, so D4 is optional *for ESD alone* — but the field cable wants
   **surge/EFT** robustness. SM712 is the correct part: asymmetric **+12 V / −7 V**
   standoff mirrors the RS485 common-mode range. (A symmetric TVS would clamp into
   the +12 V common mode.)

## 4.3 Connectivity

Pin-by-pin (`01-power.md` style).

### 4.3.1 Transceiver core
| Component / pin | Connect to | Net |
|---|---|---|
| U3 pin 8 **VCC** | `+3V3` | `+3V3` |
| U3 pin 5 **GND** | ground | `GND` |
| U3 pin 4 **D** (DI) | MCU UART2 TX (IO16) | `RS485_TX` |
| U3 pin 1 **R** (RO) | MCU UART2 RX (IO17) | `RS485_RX` |
| U3 pin 2 **RE̅** | ground (RX always on) | `GND` |
| U3 pin 3 **SHDN̅** | `SENS_PWR_EN` (gated with rail — §4.2) | `SENS_PWR_EN` |
| C60 (100 nF) pin 1 | `+3V3` (tight at U3 pin 8) | `+3V3` |
| C60 pin 2 | ground | `GND` |

Note: `RS485_TX`/`RS485_RX`/`SENS_PWR_EN` are hierarchical pins to the MCU. VCC is
the **always-on `+3V3`**, not switched 12 V — only SHDN̅ gates the part.

### 4.3.2 Bus side (A/B → connector)
| Component / pin | Connect to | Net |
|---|---|---|
| U3 pin 6 **A** | `RS485_A` node (R3 / D4 / J4) | `RS485_A` |
| U3 pin 7 **B** | `RS485_B` node (R3 / D4 / J4) | `RS485_B` |
| R3 (120 Ω) pin 1 | `RS485_A` | `RS485_A` |
| R3 pin 2 | `RS485_B` (termination across the pair) | `RS485_B` |
| D4 (SM712) **pin 1** | `RS485_A` | `RS485_A` |
| D4 **pin 2** | `RS485_B` | `RS485_B` |
| D4 **pin 3 (K)** | ground | `GND` |
| J4 pin 1 | switched sensor supply (from block 1) | `SENS_12V` |
| J4 pin 2 | `RS485_A` | `RS485_A` |
| J4 pin 3 | `RS485_B` | `RS485_B` |
| J4 pin 4 | ground (**common return — mandatory**, §4.4) | `GND` |

Note: place D4 at the connector edge; R3 close to U3. D4 (SM712.TCT) pinout confirmed
from the symbol — pins 1/2 are the two (interchangeable) line channels, **pin 3 = K
(common cathode) → GND**. A↔pin 1, B↔pin 2 (or swapped — channels identical).

### 4.3.3 Sensor-rail gate driver (the `SENS_GATE` seam → block 1)
| Component / pin | Connect to | Net |
|---|---|---|
| Q60 (2N7002) **gate** | `SENS_PWR_EN` + R60 pin 1 | `SENS_PWR_EN` |
| R60 (100 kΩ) pin 1 | Q60 gate (`SENS_PWR_EN`) | `SENS_PWR_EN` |
| R60 pin 2 | ground (default-off pulldown) | `GND` |
| Q60 **drain** | `SENS_GATE` (= block-1 Q21 gate) | `SENS_GATE` |
| Q60 **source** | ground | `GND` |
| R61 (100 kΩ) pin 1 | `SENS_GATE` | `SENS_GATE` |
| R61 pin 2 | `VBAT` (pullup) | `VBAT` |

How it works: `SENS_PWR_EN` HIGH → Q60 ON → `SENS_GATE` pulled to GND → Q21
(P-FET, source = `VBAT`) sees Vgs ≈ −12 V → ON → `SENS_12V` live. `SENS_PWR_EN`
LOW → Q60 OFF → R61 holds `SENS_GATE` at `VBAT` → Q21 OFF → rail OFF. **Default at
boot: GPIO undriven → R60 holds Q60 off → rail OFF (safety).** Matches the block-1
§1.4 contract (Q21 gate ← "2N7002 drain + 100 kΩ pullup to VBAT").

## 4.4 Remaining open items / install notes

1. **SHDN̅ gating — RESOLVED 2026-06-24: tie to `SENS_PWR_EN`** (3 µA idle). Battery
   node → favour the µA; revisit only if it causes a bring-up problem (Paul).
2. **Common-ground field cable — MUST carry all four of J4 (SENS_12V/A/B/GND).**
   The 3V3-transceiver ↔ 12V-sensor link works because RS485 is differential
   (~1.5 V swing ≫ −45 mV threshold) **only with a shared GND keeping common-mode
   inside −7…+12 V**. An installer wiring A/B/12V without the GND return is the
   failure mode — capture in the install doc.
3. **Sensor terminator** — confirm whether the chosen NPK probe embeds 120 Ω
   (→ then R3 may be DNP), §4.2 item 4.
4. **SM712 LCSC — RESOLVED (review B1, 2026-06-24):** D4 = SM712.TCT `C12067`,
   the archive-verified number, restored in the master BOM.
